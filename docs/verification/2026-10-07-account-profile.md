# Собственные аккаунты и профиль

Приложение использует собственную БД `live_slides`: `app_users` хранит логин, имя и Argon2id-хеш, `app_logins` — только хеш токена сессии. Аддитивная миграция `002-account-profile.sql` сохраняет UUID и существующие локальные аккаунты. Corp — явный дополнительный вход через `/auth/corp`, который выдаёт собственную сессию; внешняя cookie больше не авторизует API/WebSocket автоматически.

В шапке списка, настроек, профиля и выступления есть меню аккаунта: «Мой профиль» и «Выйти из аккаунта». Профиль меняет имя, логин и пароль. У аккаунта после первого входа через Corp можно задать пароль без прежнего локального пароля; затем требуется текущий пароль. Владелец сохраняет прежний UUID, презентации и личный источник. Смена пароля атомарно отзывает старые сессии, закрывает WebSocket и создаёт новый токен для текущей вкладки. Пароли и их хеши в API профиля не возвращаются. Подмена имени/логина не даёт доступ к личному источнику.

Проверка: `bunx tsc --noEmit`, JS syntax, `git diff --check`. Изолированная временная PostgreSQL/pgvector база и непривилегированная роль: миграции применены дважды; 17 тестов, 115 assertions, ошибок нет. Проверены старый/новый пароль, смена логина, конфликт логинов, CSRF, профиль только текущего пользователя, отзыв старых cookie и WebSocket, явный Corp-вход, создание локального пароля владельцу, сохранение презентаций/прав и отсутствие автоматического повторного входа после выхода. БД и роль удалены.

Headless Chromium / `playwright-cli`, 1440×1000 и 390×844: меню в рабочей области и выступлении, profile deep link/reload, изменение имени, ошибка/успех смены пароля, очистка password inputs, первоначальная установка пароля и logout. Синтетические API/данные; JavaScript errors и горизонтальное переполнение отсутствуют. Screenshots просмотрены.
