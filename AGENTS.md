# Работа с «Живыми слайдами»

Приложение распознаёт речь с микрофона и собирает слайды с опорой на документы
выбранной презентации. Дополнительный поиск в OpenViking подключается явно.
Описание и запуск — [README.md](README.md), настройки — [.env.example](.env.example),
архитектурные решения — [docs/adr/](docs/adr/).

## Изменения

- Репозиторий должен работать в самостоятельном окружении. Используйте только
  инструкции и файлы этого checkout; внешние организационные правила не являются
  зависимостью приложения или обязательной частью разработки.
- Адреса сервисов, модели, владельца дополнительного источника, registry и CDN
  задавайте через env. В примерах используйте localhost и example.org.
- Не добавляйте credentials, пользовательские документы, речь или сессии в Git,
  логи и Docker context. `data/` и локальные env-файлы исключены из Git.
- Секреты передаются окружением или явно указанными записями `pass`.
  `.env.local` содержит только несекретные настройки и имена записей.
- Публичный HTML получает только allowlist из `src/pages.ts`; не экспортируйте
  серверное окружение в браузер.
- Сохраняйте изоляцию аккаунтов и презентаций: проверки backend, PostgreSQL RLS,
  отдельные WebSocket-комнаты и пути сессий. Runtime-роль БД — без BYPASSRLS.
- Личный источник закрыт без конфигурации. Не расширяйте разрешённые scopes
  автоматически: слайды и выдержки могут видеть слушатели.

## Проверки

```sh
bunx tsc --noEmit
bun test
```

Интеграционные тесты запускайте только на отдельной тестовой PostgreSQL/pgvector
базе с `TEST_APP_PORT` и `TEST_MOCK_PORT`; без настройки они пропускаются.
Порты для локального запуска выделяет `bin/start` через `port-selector`, если
утилита доступна; также поддерживается `PORT`. Привязка по умолчанию — `127.0.0.1`.
Сквозной прогон без микрофона: `bun scripts/simulate.ts <запись.wav>`.

## Выпуск

SemVer хранится в `package.json`, изменения — в `CHANGELOG.md` под `[Unreleased]`.
Порядок выпуска — [docs/releases.md](docs/releases.md). Перед выпуском повысить
версию, выполнить проверки и зафиксировать код. Опубликованные Git-теги и
Docker-образы не переписывать. Развёртывание настраивается владельцем окружения;
этот репозиторий не требует определённого infrastructure checkout или кластера.
