# Живые слайды

Вы говорите — слайды собираются сами. Приложение распознаёт речь в реальном
времени, использует документы вашей презентации и готовит следующий слайд
заранее. Уже сказанное отличается от прогнозов; когда тема меняется,
несбывшиеся прогнозы снимаются.

**[Сайт и ранний доступ](https://live-slides.pismenny.ru)** ·
[Принятые решения](docs/adr/) · [История изменений](CHANGELOG.md) ·

## Возможности

- Список презентаций, отдельные настройки материалов и режим выступления.
- Загрузка TXT, PDF, DOC и DOCX; сканы PDF распознаются через OCR.
- Поиск по документам выбранной презентации через PostgreSQL/pgvector.
- ElevenLabs Scribe Realtime или локальный Whisper для распознавания речи.
- OpenAI-совместимый LLM endpoint для слайдов и вариантов продолжения мысли.
- Собственные аккаунты, профиль, смена пароля и выход.
- Дополнительный OpenViking-источник только для явно настроенного владельца.
- Сохранение и восстановление слайдов и речи отдельно для каждой презентации.

Приложение в раннем доступе. Самостоятельная регистрация и совместный доступ
к презентациям пока не включены.

## Запуск в своём окружении

Нужны Bun, PostgreSQL с pgvector, OpenAI-совместимый LLM/embedding endpoint,
`pass` и `direnv`. Для PDF/OCR/DOC нужны Poppler, Tesseract (`rus+eng`) и
antiword; для DOCX — Tika Server. В Docker установлены локальные экстракторы.

```sh
bun install --frozen-lockfile
cp .env.example .env.local
# Укажите свои endpoint, модели и имена записей pass в .env.local.
direnv allow
direnv exec . bun scripts/migrate.ts
direnv exec . bun scripts/create-user.ts presenter "Докладчик" your/pass/account-password
direnv exec . bin/start
```

Откройте адрес, напечатанный `bin/start`, войдите на `/app/`, создайте
презентацию и загрузите материалы. Когда документы получат статус «Готов»,
начните запись. Вторая вкладка показывает ту же презентацию для проектора;
микрофон остаётся в первой.

`bin/start` выделяет локальный порт через `port-selector --name web`, если
утилита установлена; иначе использует `4747`. При ручном выборе порта
`APP_ORIGIN` должен совпадать с адресом в браузере.

## Конфигурация и секреты

Все настройки окружения находятся в [`.env.example`](.env.example) и
[`src/config.ts`](src/config.ts). `.env.local` содержит только несекретные
параметры и имена записей `pass`. `.envrc` загружает credentials в переменные
окружения; backend также умеет читать явно указанную запись `pass` напрямую.

| Назначение | Переменные |
|---|---|
| Приложение | `HOST`, `PORT`, `APP_ORIGIN`, `DATA_DIR`, `PROMPTS_DIR` |
| База документов и аккаунтов | `DATABASE_PASS_ENTRY` → `DATABASE_URL`, `DATABASE_HOST` |
| Слайды | `LLM_BASE_URL`, `LLM_MODEL`, `LLM_KEY_PASS_ENTRY` → `LLM_API_KEY` |
| Векторы | `EMBEDDING_BASE_URL`, `EMBEDDING_MODEL`, `EMBEDDING_KEY_PASS_ENTRY` → `EMBEDDING_API_KEY` |
| Речь | `STT_ENGINE`, `SPEECH_LANGUAGE`, `ELEVENLABS_PASS_ENTRY`, `WHISPER_MODEL` |
| Вход по коду на почту | `SMTP_URL`, `SMTP_PASSWORD_PASS_ENTRY` → `SMTP_PASSWORD`, `MAIL_FROM` |
| Личная память | `PERSONAL_SOURCE_SUBJECT`, `OPENVIKING_*`, `SOURCE_SCOPES` |
| Дополнительный вход | `CORP_VERIFY_URL`, `CORP_LOGIN_URL`, `CORP_OWNER_USER` |
| Публичная страница | `PUBLIC_SITE_URL`, `PUBLIC_AUTHOR_*`, `PUBLIC_INTRO_*` |
| Заявки на ранний доступ → Sales CRM (Twenty) | `TWENTY_API_URL`, `TWENTY_API_KEY_PASS_ENTRY` → `TWENTY_API_KEY`, `CRM_SOURCE_SYSTEM`, `CRM_PRODUCT_TIER` |
| Образ и CDN | `APP_IMAGE_REPOSITORY`, `PUBLIC_SITE_MEDIA_CDN_*` |

Промпты режиссёра и подсказка распознавателю лежат в [`prompts/`](prompts/):
`director.md` — системный промпт, `paths.md` — добавка режима вариантов,
`speech-terms.txt` — термины и стиль речи для Whisper. `PROMPTS_DIR` подменяет
папку целиком при развёртывании. Презентация может переопределить свою
инструкцию режиссёра и термины и добавить описание выступления (поля
`director_prompt`, `talk_brief`, `speech_terms`, миграция 004); пустое поле —
стандартный текст.

Аккаунт с почтой входит по одноразовому коду из письма (`POST /api/auth/code`,
затем `/api/auth/code/verify`; код — шесть цифр, десять минут, пять попыток,
одно письмо в минуту; миграция 005). Такой аккаунт создаёт
`bun scripts/invite-user.ts <login> <имя> <почта>`; пароль он может задать в
профиле. Без `SMTP_URL`, `MAIL_FROM` и пароля форма показывает только вход по
логину и паролю.

Заявки с публичной страницы хранятся в таблице `waitlist_requests` (миграция
003) и уходят в Sales CRM как intake lead по контракту `sales-intake/v1`;
недоставленные повторяются каждые пять минут, посетитель ошибок CRM не видит.
Без `TWENTY_API_URL` и ключа заявки остаются только в базе. Файл
`waitlist.jsonl` прежних версий переносится в базу при первом запуске.

Не записывайте секреты в `.env.local`, Git, документацию или CLI-аргументы.
В контейнере значения передаются через secret-механизм вашей инфраструктуры.
Ключи не отправляются в браузер. LLM и embeddings могут передавать текст
провайдеру выбранного endpoint; ElevenLabs получает звук. Whisper работает
локально. Для локальной модели есть `scripts/download-model.sh`.

## Изоляция и личная память

Каждый аккаунт видит только свои презентации и документы. Backend проверяет
владельца, PostgreSQL применяет RLS; runtime-роль должна быть без
SUPERUSER/BYPASSRLS. Пароли хранятся как Argon2id-хеши, сессии — как хеши
токенов. После смены пароля старые сессии и WebSocket отзываются.

Corp-вход и личный источник выключены без явной конфигурации. Для владельца
задаются `CORP_OWNER_USER` и стабильный `PERSONAL_SOURCE_SUBJECT=corp:<username>`.
Backend проверяет настоящую cookie через `CORP_VERIFY_URL` и выдаёт собственную
сессию. Совпадение имени или логина локального аккаунта не даёт доступа к памяти.
`bootstrap-owner.ts` создаёт первую презентацию настроенного владельца,
не копируя личные материалы. Разрешённые `SOURCE_SCOPES` задаются явно;
по умолчанию список пуст. Не включайте материалы, которые нельзя показать аудитории.

Документы: до 20 МБ на файл, 60 страниц PDF, 1 млн символов текста; до 200 МБ,
200 документов и 50 презентаций на аккаунт. Изменение размерности векторов
требует миграции и переиндексации: текущая схема использует 1024 измерения.
Обработка восстанавливается после перезапуска; поиск видит только готовые фрагменты.

## Управление выступлением

| Клавиша | Действие |
|---|---|
| Пробел | начать или остановить запись |
| N | новый слайд сейчас |
| V | варианты продолжения мысли |
| ← → | листать слайды; L — вернуться к живому |
| F | полный экран |
| D | тёмная тема |
| T | скрыть ленту речи |

Сессии сохраняются в `data/users/<user-id>/projects/<project-id>/sessions/`:
`deck.json`, `deck.md`, `transcript.jsonl`, `metrics.jsonl`. `data/` исключён из
Git и контекста Docker-сборки. CLI-симуляции сохраняются отдельно в `data/sessions/`.

## Проверки и выпуск

```sh
bunx tsc --noEmit
bun test
gitleaks git --log-opts=--all --redact
```

Интеграционные тесты запускайте только с отдельной тестовой БД и
`TEST_APP_PORT` / `TEST_MOCK_PORT`. Без этих параметров тесты БД пропускаются.
Для сквозного прогона без микрофона: `bun scripts/simulate.ts recording.wav`;
для экстракторов — `DOCUMENT_TEST_FIXTURES` и `TIKA_URL`.

Версия хранится в `package.json`, видна в профиле и `GET /version`. Выпуск по
SemVer и неизменяемые Git/Docker-теги описаны в [docs/releases.md](docs/releases.md).
Deployment выполняется через infrastructure runbook выбранного окружения.

## Формат дополнительного индекса

Для OpenViking задайте адрес, identity, корень ресурсов и разрешённые scopes.
Scopes — имена разделов под вашим корнем; принадлежность к определённой
организации или структуре репозиториев не требуется. Без дополнительного
индекса приложение использует документы выбранной презентации.

Обычный Markdown поддерживается без служебных вставок. При необходимости
можно добавить происхождение фрагмента:

```markdown
<!-- source-metadata {"source":"repo://owner/materials/talk.md","repository":"materials"} -->
```

Имя маркера переопределяется через `SOURCE_METADATA_MARKER`, чтобы использовать
существующий индекс с другим форматом метаданных. URL, root, scopes и ключ
остаются серверной конфигурацией.
